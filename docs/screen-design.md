# 画面設計書

## 1. 共通方針
- 日本語UI、iPhone縦向き。
- Dynamic Typeで文字を大きくしても操作できるレイアウトとする。
- ライト／ダークモードはシステム設定に追従する。
- 保存や再計算のエラーはユーザーが理解できる日本語で表示し、可能な場合は再試行方法を提示する。
- 入力エラーは可能な限り該当項目の近くに表示する。

## 2. S-01 週間献立
### 表示項目
- 対象週（月曜日〜日曜日の日付）
- 前週へ／翌週へ
- 曜日ごとの料理一覧
- 料理名と人数
- 料理追加、献立から削除
- 買い物リストへ移動
- レシピボタン（常設。レシピの有無や献立の有無にかかわらず表示）
- 他週の献立をコピー
- レシピ未登録時の登録案内

### 操作
- 週移動で月曜日を基準にした週を切り替える。
- レシピボタンでS-02を管理モードで開く。
- 料理追加でS-02を選択モードで開き、選択したレシピを当該曜日に追加する。
- 同じ料理を複数回追加できる。
- 人数変更は1〜99の整数のみ許可する。全角数字は半角に変換して受け付ける。先頭の0は受け付ける（「05」「０５」は5）。
- 献立から料理を削除しても、レシピ本体は削除しない。
- 週コピーのコピー先は表示中の週に固定する。ユーザーはコピー元の週だけを選択し、初期値は前週とする。
  - コピー元の週に献立がない場合、またはコピー元が表示中の週と同じ場合は実行できない。
  - コピー先に献立がある場合は置き換え確認を表示する。承認時のみコピー先の週全体を置き換え、キャンセル時は変更しない。
  - コピー先に献立がない場合は確認なしでコピーする。
- 献立に変更があった場合、買い物リストを再計算する。再計算失敗時は旧リストを維持し、エラーを表示する。

### 空状態
- レシピが0件：レシピ登録を案内する。
- レシピはあるが週の献立が0件：料理を追加するよう案内する。

## 3. S-02 レシピ一覧
S-02には、開き方によって2つのモードがある。

| モード | 開き方 | レシピをタップ | 追加 | 編集 | 削除 |
|---|---|---|---|---|---|
| 管理モード | S-01のレシピボタン | S-03で編集 | 可 | 可 | 可 |
| 選択モード | S-01の料理追加 | 当該曜日へ追加してS-01へ戻る | 可 | 不可 | 不可 |

### 表示項目
- レシピ名
- 必要に応じて基準人数
- レシピ追加ボタン（両モード）
- 編集・削除操作（管理モードのみ）

### 操作
- 追加・編集はS-03へ遷移する。編集は管理モードでのみ行える。
- 選択モードでレシピを追加した場合、保存またはキャンセル後は選択モードのS-02へ戻る。新規登録したレシピは献立へ自動追加しない。献立へ追加するには一覧から選択する。
- 削除は管理モードでのみ行える。確認ダイアログを表示し、確認後、レシピ、材料、全週の関連献立登録を削除する。キャンセル時は何も変更しない。
- 削除処理が失敗した場合は全削除を取り消し、エラーを表示する。

## 4. S-03 レシピ登録・編集
### 項目
- レシピ名（必須）
- 基準人数（必須、1〜99の整数）
- 材料行（0件以上）
  - 材料名
  - 数量種別：数値／文字
  - 数値数量または文字数量
  - 単位（数値数量の場合のみ表示し、必須。文字数量の場合は入力欄を表示しない）
  - 表示順
- 参考URL（任意）
- メモ（任意）
- 保存、キャンセル

### 入力ルール
- レシピ名は空白のみ不可。
- 基準人数は1〜99の整数。全角数字は半角に変換して受け付ける。先頭の0は受け付ける（「05」「０５」は5）。
- 入力した材料行は材料名必須。材料名は前後の半角・全角空白を除去して保存する。
- 数値数量は0より大きく99999以下の小数。全角数字と全角小数点「．」は半角に変換する。空欄、0、負数、99999超、カンマ入り、「.5」「5.」のように小数点の前後に数字がない入力、数値として解釈できない入力、20文字を超える入力はエラーとする（数え方と処理順はデータ設計書3.1）。
- 数値数量の単位は必須。自由入力とし、前後の半角・全角空白を除去したうえで入力した表記のまま保存する。除去後に空欄となる場合はエラーとする。
- 文字数量は空欄不可（例：少々、適量）。前後の半角・全角空白を除去して保存し、除去後に空欄となる場合はエラーとする。単位は保存しない。
- URL入力時はURL形式を検証。
- 材料が0件でも保存可能。
- 重複するレシピ名・材料名を許可する。

### 保存値が不正な材料がある場合
保存されている数量が不正な材料（データ設計書3.1の「保存値の再読み込み時の検証」で不正と判定されたもの）を含むレシピを開いた場合:
- 不正な材料の行に、その項目（数値数量）が不正であることを示すエラーを表示する。
- 不正な値を推測で補正したり、0に置き換えたりしない。入力欄は再入力できる状態にする。
- 画面を開いただけでは保存しない。元のデータは、ユーザーが正しい値を入力して保存するまで変更しない。
- 保存時は通常の入力ルールで全行を検証する。不正な行が残っている場合は保存せず、エラーを表示して入力内容を保持する。
- キャンセルした場合、または未保存変更の確認で「破棄する」を選んだ場合は、元のデータ（不正な値を含む）をそのまま保持する。
- 不正な材料があることを理由に、ほかの正常な材料やレシピの項目を変更しない。

### 未保存変更
画面を離れる際、未保存の変更があれば確認を表示する。
- 編集を続ける：画面に留まり入力内容を保持。
- 破棄する：未保存変更を捨てて戻る。
- 保存する：検証し、成功時のみ保存して戻る。入力エラーがあれば画面に留まり内容を保持する。

## 5. S-04 買い物リスト
### 表示項目
- 選択週
- 材料名
- 必要量と単位。単位が異なる場合は別数量として表示
  - 数値は、最終的な合算結果を小数第2位に四捨五入し、末尾の0を省略する。正の値が丸めによって0になる場合は「0.01未満」と表示する（データ設計書3.3）。
  - 既知単位は g または ml に換算して表示する。
  - 文字数量は倍率計算せずそのまま表示する。同じ材料の同じ文字数量は1つにまとめ、異なる文字数量は区別して表示する。
- 購入済みチェック
- 項目の手動削除
- 再計算失敗時の古いリスト警告と再試行操作（再計算が必要な状態はアプリ再起動後も表示する）

### 操作・状態
- 買い物リストの表示だけでは再計算しない（再計算が不要な場合）。
- 手動削除はリストからのみ除外し、レシピや献立を変更しない。
- 購入済み状態は週ごとに保存する。
- 献立、人数、レシピ材料、調味料辞書等の変更による再計算成功時は、対象週の手動削除・購入済み状態をリセットする。
- 再計算失敗時は旧リストと状態を保持し、古い可能性を表示する。

## 6. S-05 設定
### 項目
- 調味料辞書の一覧
- 調味料名追加
- 調味料名削除
- バックアップ・復元への導線
- アプリ情報

### 入力ルール
- 調味料名は前後の半角・全角空白を除去して保存する。除去後に空欄となる名前、および既存と重複する名前は不可。
- 調味料辞書を変更した場合、その調味料名と完全一致する材料を含む週だけを再計算する。再計算成功時に対象週の手動削除・購入済み状態をリセットする。
- 保存に失敗した場合は旧設定を維持する。

## 7. S-06 バックアップ・復元
### バックアップ
- JSON書き出し操作
- 処理中状態
- 成功／失敗メッセージ
- 失敗時の再試行

### 復元
- iOSファイル選択UIでJSONを選ぶ
- ファイル検証結果
- 既存データを置き換える旨の確認
- キャンセル／復元実行
- 成功／失敗メッセージ
- 復元できなかった購入済み・手動削除状態の件数（1件以上ある場合）

不正形式、非対応バージョン、データ整合性エラー（ID重複、関連付けの不整合を含む）、復元中の再計算または保存の失敗の場合は現行データを変更しない。復元キャンセル時も変更しない。

## 8. 画面遷移
- 起動 → S-01
- S-01のレシピボタン → S-02（管理モード）
- S-01の料理追加 → S-02（選択モード。選択後S-01へ戻る。編集・削除不可）
- S-02の追加／編集 → S-03（保存／キャンセル後、元のモードのS-02へ戻る）
- S-02（管理モード）の削除 → 削除確認ダイアログ
- S-01 → S-04
- S-01 → S-05
- S-05 → S-06
