# テスト設計書・テスト結果一覧

## 1. 方針
- 自動テストと手動テストを組み合わせる。
- 数量計算、材料集約、日付計算、入力検証、データ操作、バックアップ／復元は可能な限り自動テストする。
- UI、画面遷移、Dynamic Type、ダークモードは手動でも確認する。
- iOSシミュレーターと実機iPhoneの両方で確認する。
- 定義済みのすべてのテスト項目が成功するまでテスト完了としない。
- 不具合修正後は該当テストを再実行し、影響範囲に応じて回帰テストする。
- テスト結果は各項目の実施結果・合否・不具合を記録する。

## 2. 合否の記録値
- 未実施
- 成功
- 失敗

公開準備を検討する時点で「未実施」「失敗」が1件でも残っている場合、完了と判断しない。軽微な表示崩れも修正して成功を確認する。

## 4. テスト結果の記録欄
各実行時に次の情報を記録する。
- 実施日
- テストID
- 実行環境（シミュレーター／実機、iOSバージョン）
- 実施結果（実際に確認できた内容）
- 合否（未実施／成功／失敗）
- 不具合内容・再現手順
- 修正コミットや再テスト結果

## 5. 完了条件
- 全テスト項目が実施済みで、合否がすべて成功である。
- 失敗した項目は修正後に再テストされ、成功している。
- 重要機能はシミュレーターと実機で確認されている。
- ビルド／テストを実行できなかった項目は成功扱いにしない。
